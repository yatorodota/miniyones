# МИНЬОНЫ — сайт клана в Minecraft

Статический сайт (HTML + CSS + JS, без бэкенда и сборки) в «пиксель-HUD»-стиле: интерфейс как у тактического дисплея, **белый фон**, тонкие линии-сетки, лента событий, scanlines, параллакс, пиксельный шрифт в микро-подписях и плавное появление секций при скролле. Графика — яркие иллюстрации в стиле миньонов (собственные SVG, не пиксель-мобы). Игра ванильная: без модов и плагинов. Связь с кланом — только через Discord, заявки тоже туда. Работает на любом бесплатном статическом хостинге «как есть».

├── .nojekyll             отключает Jekyll на GitHub Pages

    ├── css/admin.css     стили панели

## Дизайн

- **белый фон — основной цвет**: `--bg #ffffff`, панели `#f6f6f4` / `#ececeb`, текст `#050607`, акценты и кнопки — чёрные по белому;
- графика: цветной миньон в hero, четыре кадра галереи (стройка, вместе, полёт, схема) и favicon — все собственные SVG в `assets/img/`;
- тёмные полосы оставлены только как акценты: верхний статусбар и меню — полупрозрачно-белые, кнопки и бейджи инвертированы (чёрный фон + белый текст);
- шрифты: `Unbounded` (заголовки), `JetBrains Mono` (техтекст), `Press Start 2P` (номера секций, счётчики, микро-подписи), `Inter` (интерфейс);
- блочная сетка 17 px как «текстура блоков», watermark силуэта миньона в блоке «Вступить»;
- секции пронумерованы `01–04` (о клане, участники, правила, навыки), у каждой своя подпись и HUD-панель;
- внутри «Участников» — рейтинг города по звёздам;
- бегущие счётчики статистики, карточки лидера и заместителя, сетка участников, правила и CTA;
- адаптив: десктоп / планшет / телефон, бургер-меню, поддержка `prefers-reduced-motion`;
- контраст текста проверен автоматически: минимум 4.4:1 по WCAG AA, белый текст только на чёрных плашках.

## Ранги по умолчанию

`глава` → `зам` → `доверенный` → `участник`. Названия и цвета меняются во вкладке «Ранги».

## Аккаунты, публикации и звёзды

Страница `account.html`:

- **регистрация по коду приглашения** — свой ник (латиница, цифры, `_`, `-`, 3–16 символов), **обязательный ник в Discord** (2–32 символа, буквы/цифры/пробел/`_`/`.`/`-`) и пароль от 4 символов; без кода аккаунт не создаётся. Ник в Discord сохраняется в аккаунте, виден в профиле игрока и в панели (вкладка «Игроки», там же работает поиск по нему). Пароль не хранится открыто, от него считается хеш с солью (`SHA-256`, метка `s1:`, запасной вариант `w1:` для браузеров без WebCrypto);
- **Регистрация только по коду** - ник (латиница, цифры, _, -, 3-16 символов) + ник в Discord (обязательно) + пароль от 4 символов; без кода приглашения аккаунт не создаётся. Пароль хранится только хеш, не сам пароль, и вход (SHA-256, соль s1:, минимум 5000 итераций WebCrypto);
- **Рейтинг города** - место по звёздам, до следующего ранга 5 звёзд, место игрока подсвечивается, можно смотреть работы других игроков и оставлять блок <ВСТУПИТЬ // ГОРОД>.
### Discord

На сайте есть **только ссылка на Discord**: <https://discord.gg/8X4KR2H9xU>. Она прописана в config.discord и в data/clan.json и показывается в четырёх местах: кнопка <Оставить заявку> в шапке, блок <СВЯЗЬ // DISCORD> на главной (ссылка с копированием по клику и кнопка <Вступить в Discord>), контакт <Discord> в подвале и кнопка заявки в блоке <Вступить>.

Привязки аккаунта к Discord, OAuth, проверки ников и счётчиков онлайна на сайте нет - игрок просто жмёт на ссылку и пишет в Discord сам.

Своего игрового сервера у клана нет, поэтому на сайте нет ни IP, ни порта, ни версий Java/Bedrock, ни слова «сервер». Клан - это сообщество игроков: общение, заявки и набор идут через Discord.


### Коды приглашения

Аккаунт создаётся **только по коду**. Глава клана делает коды в `admin.html` → вкладка **«Коды»**: либо нажать быструю кнопку (1 / 5 / 10 / **30** / 50 кодов), либо указать количество вручную (1–50), можно выдать код конкретному нику и добавить заметку → «Создать коды». Дальше коды отправляются игрокам в личку, кнопка «Копировать свободные» кладёт в буфер весь список сразу.

Формат кода: `MNY-XXXX-XXXX` (без похожих символов `0/O` и `1/I`). Один код — один аккаунт: при регистрации код списывается и помечается «ИСПОЛЬЗОВАН · ник». Повторно он не работает, и другой ник его не использует. Код, выданный конкретному нику, работает только у этого ника. В списке есть «Вернуть в свободные» (сбросить списание) и «Удалить».

Коды создаются в том браузере, где открыта админка (`localStorage`, ключ `minteny_codes_v1`), **но сайт подтягивает их и из файла**: при регистрации `minty.js` один раз грузит `data/clan.json` и добавляет в свой список все коды из массива `codes`, которых у него ещё нет. Поэтому игрок со своего телефона увидит твои коды, если они лежат в залитом файле.

**Чтобы коды работали у игроков (важно):**
1. `admin.html` → «Игроки» → создай коды.
2. Нажми **«Скачать clan.json с кодами»** (в выгрузку попадает массив `codes`).
3. Замени файл `data/clan.json` в проекте на скачанный.
4. Залей папку на хостинг заново.

Если этот шаг пропустить, игрок с верным кодом получит «Код не найден» — у него в браузере списка кодов нет. Списание кода (и аккаунты, публикации, звёзды) остаётся в браузере игрока; чтобы увидеть их в панели, нужен экспорт/импорт JSON или перенос на Supabase.

**Как проверить, что коды доехали до хостинга:** в панели, в блоке кодов, есть кнопки «Скачать clan.json с кодами» и «Проверить файл на сайте». Вторая честно грузит `data/clan.json` с хостинга (с обходом кэша) и пишет: сколько кодов на сайте, сколько свободных и каких твоих кодов там не хватает. На странице регистрации игрок тоже видит строку «КОДОВ НА САЙТЕ: N // СВОБОДНЫХ: N» — если там 0, файл на хостинг не залит.

### Ограничения

**Лимитов на количество и частоту регистрации нет**: сколько кодов выдал глава, столько игроков и смогут зайти. Единственный барьер — код приглашения, и он одноразовый. Считаются только ошибки:

| что | ограничение |
|---|---|
| неверный код | 5 попыток → пауза в регистрации на 15 минут |
| вход | 5 неверных паролей → 5 минут, 10 попыток → 1 час |
| публикация | 1 за 10 минут, максимум 3 в очереди и 10 в сутки |

Все значения меняются в объекте `LIMITS` в начале `assets/js/minty.js`. Точные тексты ошибок отдаёт `Minty.guardInfo()` и `Minty.fmtWait()`.

> Эти лимиты и коды — честная защита от случайного спама в рамках демо-режима. Обойти их можно, просто очистив localStorage: настоящая защита от массовой регистрации — только на сервере (Supabase RLS, Cloudflare Worker, своя авторизация).

Как начисляется звезда: игрок отправляет публикацию → в `admin.html` открыть вкладку **«Публикации»** → «Засчитать» → игрок получает `+1 звезда`, публикация становится «ЗАСЧИТАНО +1★». «Отклонить» — без звезды, «Вернуть в очередь» — откат статуса (звезда при этом не снимается). Одна публикация может начислить звезду только один раз: у поста есть флаг `awarded`, поэтому повторное одобрение уже засчитанной работы не даёт `+2`.

Ранги в городе считаются автоматически:

| звёзды | ранг |
|---|---|
| 0–2 | Новичок |
| 3–5 | Житель |
| 6–9 | Строитель |
| 10–14 | Мастер |
| 15+ | Легенда |

### Управление аккаунтами игроков

В `admin.html` появилась вкладка **«Игроки»** — управление аккаунтами, которые зарегистрировались через код приглашения. Для каждого игрока:

| действие | как |
|---|---|
| выдать роль | выбрать роль прямо в строке (`ИГРОК`, `УЧАСТНИК`, `СТРОИТЕЛЬ`, `МОДЕРАТОР`, `ЗАМ ГЛАВЫ`, `ГЛАВА`) |
| звёзды | `+1★`, `−1★` или «Звёзды…» — задать число сразу (0…9999) |
| сменить ник | «Ник…» — с проверкой длины, символов, занятости и зарезервированных ников; код приглашения остаётся за этим же игроком |
| заметка | «Заметка…» — видно только в панели |
| сбросить пароль | «Пароль…» — задаёт новый пароль игроку, старая соль и хэш пересчитываются |
| выдать код | «Код» — новый код приглашения, привязанный к нику игрока |
| бан / разбан | «Забанить» с причиной; забаненный не может ни войти, ни зарегистрироваться |
| удалить | «Удалить» — аккаунт и его публикации удаляются, код возвращается в свободные, бан снимается |

Есть поиск (ник, Discord, роль, заметка), фильтр по роли, сортировка (звёзды / дата входа / ник / активность) и массовые действия: выдать роль или начислить звёзды сразу всем аккаунтам. Выданная роль показывается в рейтинге города на главной (`app.js`) и в кабинете игрока.

Список обновляется сам, когда данные меняются в другой вкладке или на сайте. Функции доступны и из консоли: `Minty.adminUsers()`, `Minty.setRole(id, role)`, `Minty.addStars(id, ±1)`, `Minty.setStars(id, n)`, `Minty.editUser(id, {nick, role, note})`, `Minty.setUserPassword(id, pass)`, `Minty.banUser(id, reason)`, `Minty.unbanUser(id)`, `Minty.codeForUser(id)`, `Minty.deleteUser(id, {freeCode: true})`.

> Как и коды, аккаунты лежат в `localStorage`: панель управляет только аккаунтами, созданными **в этом браузере**. У игрока на своём устройстве они свои. Общее управление игроками появится вместе с бэкендом — набор функций уже готов, меняется только источник данных.

> **Важно: сейчас это демо-режим.** Сайт статический, без сервера, поэтому аккаунты, пароли, публикации, звёзды и коды приглашения лежат в `localStorage` одного браузера. Заявка, отправленная на одном компьютере, не появится у другого игрока. Код админки — простая блокировка от случайных посетителей, а не настоящая защита.
> Чтобы регистрация работала по-настоящему (общий вход с разных устройств + очередь заявок у главы), нужен бесплатный бэкенд. Подойдёт **Supabase** (бесплатно, без карты): регистрация по email+паролю, таблица `posts`, хранилище для скринов. Он пока **не подключён**: для подключения нужно заменить функции `register` / `login` / `submit` / `setStatus` в `assets/js/minty.js` на вызовы Supabase — остальной код (профиль, звёзды, рейтинг, админка) остаётся как есть. Текущие имена ключей хранилища перечислены в `Minty.KEYS` — это ключи `localStorage`, а не ключи Supabase.

## Как опубликовать (бесплатно)

Сайт статический, поэтому подойдёт любой хостинг без сервера и базы данных.

### Netlify Drop — 30 секунд, без регистрации
1. Открой `https://app.netlify.com/drop`.
2. Перетащи папку `clan-site` (или zip `mineny-site.zip`) в окно браузера.
3. Через 10–20 секунд сайт откроется по адресу `https://<имя-проекта>.netlify.app`.
4. **Site configuration → Change site name** — задай постоянное имя, например `minteny.netlify.app`.
5. **Site configuration → Add custom domain** — свой домен подключается в пару кликов, HTTPS выпустится сам.

### Cloudflare Pages
1. `dash.cloudflare.com` → **Workers & Pages → Create → Pages → Upload assets**.
2. Загрузи ту же папку `clan-site` → **Deploy**.
3. Адрес проекта: `https://<имя-проекта>.pages.dev`, свой домен — **Pages → Custom domains**.
4. Обновление: **Create a new deployment** и снова загрузить папку.

### Vercel
1. `vercel.com` → **Add New → Project → Deploy**, либо в терминале в папке `clan-site` выполнить `npx vercel`.
2. Адрес: `https://<имя-проекта>.vercel.app`, домен — **Settings → Domains**.

### GitHub Pages
1. Создай репозиторий, скопируй в него содержимое `clan-site`.
2. `git add . && git commit -m "init" && git branch -M main && git push -u origin main`.
3. **Settings → Pages → Source: Deploy from a branch → Branch: `main`, folder: `/ (root)` → Save**.
4. Сайт откроется по адресу `https://<твой-логин>.github.io/<имя-репозитория>/`.

## Как добавлять ники, кадры и видео

1. Открой `admin.html` (например `https://<адрес-сайта>/admin.html`).
2. Введи код доступа и заполни форму — данные сохранятся в браузере.
3. Нажми **«Скачать clan.json»** на вкладке «Данные».
4. Замени файл `clan-site/data/clan.json` на скачанный.
5. Залей обновлённую папку на хостинг заново (Netlify: **Trigger deploy**, Cloudflare: новая загрузка, Vercel: `npx vercel`, GitHub Pages: `git push`).
6. После этого изменения увидят все посетители сайта.

> Важно: панель — это статическая страница без сервера. Правки в браузере хранятся в `localStorage` только у вас. Чтобы обновить сайт для всех, нужен шаг 4–5: заменить и залить `data/clan.json`. Код доступа — простая блокировка от случайных посетителей, а не настоящая защита (значение по умолчанию лежит в открытом `assets/js/config.js`).
>
> **Если меняете `data/clan.json` — поднимите в нём `"version"`.** Поле `version` вверху файла сравнивается с тем, что лежит в `localStorage` посетителя. Если версия файла новее (или её не было), сайт при загрузке сам подтягивает свежие тексты/ссылки/переключатели из файла, сохраняя ваши правки участников, рангов и навыков. Без поднятия `version` браузер продолжит показывать старые значения из `localStorage`. Текущая версия — **3**.

## Замена изображений

- Портрет и кадры — это SVG (`assets/img/hero.svg`, `assets/img/frame-01…04.svg`): нарисованные миньоны. Раздел с кадрами удалён, файлы `frame-01…04.svg` оставлены как запас. Чтобы поставить настоящий скриншот в hero, замените `assets/img/hero.svg` или укажите новый путь в панели (поле изображения hero). Обо всех используемых файлах изображений можно прочитать в `assets/js/config.js` и `data/clan.json`.
- Аватары участников подтягиваются с `mc-heads.net` по нику.

## Локальный запуск

Откройте `index.html` двойным кликом (работает, кроме загрузки `data/clan.json` — тогда берутся значения по умолчанию), либо запустите локальный сервер:

```
py -3 -m http.server 8765 --bind 127.0.0.1
```

и откройте `http://127.0.0.1:8765/`. Страница аккаунта — `http://127.0.0.1:8765/account.html`, панель — `/admin.html`.

| файл | что делает |
|---|---|
| `index.html` | главная |

| `assets/css/account.css` | страница кабинета |
| `assets/css/style.css` | белая тема сайта: токены в `:root`, HUD-сетка, hero |
| `data/clan.json` | данные, которые видят все посетители |
